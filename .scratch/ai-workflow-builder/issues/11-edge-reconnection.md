# 11 — Edge reconnection on the canvas

> *This was generated by AI during triage.*

**Status:** resolved

Reported: existing edges on the workflow canvas cannot be edited. Verified against the codebase: creating a new edge (drag handle to handle) and deleting a selected edge both work, but there is no way to drag an existing edge's endpoint to reconnect it to a different node/handle — the wiring library's reconnect capability was never enabled. A user who wants to rewire one edge must delete it and redraw it from scratch, which loses any edge-specific state and is easy to mis-click on a busy graph.

## Agent Brief

**Category:** bug
**Summary:** Existing edges on the workflow canvas cannot be reconnected by dragging an endpoint — only created (new connection) or deleted.

**Current behavior:**
On the canvas, an edge can be created by dragging from a source handle to a target handle, and an edge can be removed by selecting it and pressing Delete. There is no interaction for grabbing an existing edge's endpoint and dragging it onto a different node/handle to rewire it in place.

**Desired behavior:**
A user can grab either endpoint of an existing edge and drag it onto a different valid target/source handle to reconnect the edge, without deleting and recreating it. The same connection-validity rules that already govern creating a new edge (an Agent node's outgoing edge must terminate at an End node; a Start node must not connect directly to an End node; a source handle may not already have an outgoing edge; no self-loops) must also govern reconnection — an invalid drop should cancel and leave the original edge unchanged. Edge creation and deletion behavior must be unaffected.

**Key interfaces:**
- The canvas edge-wiring surface (currently wired via `onConnect`/`isValidConnection`/`onEdgesChange` on the React Flow instance) needs its reconnect handler enabled and wired the same way `onConnect` is — reusing the existing connection-validity check rather than duplicating it.
- Edges need to opt into being reconnectable (the library's per-edge/global "reconnectable" flag), analogous to how nodes already carry a `deletable` flag for the fixed Start/Agent/End trio.

**Acceptance criteria:**
- [x] Dragging an existing edge's endpoint onto a new valid target reconnects the edge in place (same edge id or a clean replacement — no duplicate edge left behind)
- [x] Dragging an existing edge's endpoint onto an invalid target (fails the existing connection-validity rules) leaves the original edge unchanged
- [x] Reconnecting an edge and saving persists the new source/target through the same graph schema the backend already reads
- [x] Creating a brand-new edge (handle-to-handle drag) and deleting a selected edge continue to work unchanged
- [x] Verified with a manual or automated interaction test (e.g. Playwright), not just a code read

**Out of scope:**
- Changing which node-type pairings are valid connections (the existing validity rules are reused, not revisited)
- Any change to the fixed Start→Agent→...→End topology constraints
- Read-only/preview mode (reconnection is an edit-mode-only interaction, same as node dragging)
